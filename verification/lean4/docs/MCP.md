# Lean MCP-сервер и инструменты разработки (замечание №8)

Цикл «правка доказательства — сборка — диагностика» сокращают два средства:

## 1. lean4-mcp / LSP-инспекция целей

Инструменты AI-ассистента (MCP-протокол) и LSP-сервер Lean дают одно и то же
ядро: инспекцию целей (`goal` / `Tactic state`), диагностику на лету и поиск
теорем Mathlib по сигнатуре. Подключение к этому репозиторию:

```bash
# LSP (редактор): открыть verification/lean4 как рабочую папку —
# .lean-toolchain уже закреплён (v4.6.0), lakefile.lean резолвит Mathlib
# тегом v4.6.0; VS Code + lean4 extension подхватят автоматически.

# MCP (AI-ассистент в редакторе): lean4-mcp подключается к тому же lake-
# проекту; в промптах доступна инспекция целей текущего доказательства
# и ПОИСК ПО MATHLIB (theorem search) прямо в цикле правки.
```

## 2. Быстрая синхронная итерация (то, чем формализация и писалась)

```bash
export ELAN_HOME=<elan> PATH=<elan>/bin:$PATH
cd verification/lean4
lake env lean Trivortex.lean > /tmp/iter.log 2>&1   # ~3 мин: вся ×10 секций
grep -n "error" /tmp/iter.log                        # диагностика
```

Чанковая дисциплина для больших правок: вырезать секцию в отдельный файл с
теми же импортами, итерировать `lake env lean chunk.lean`, затем сплайсить
обратно и прогонять полный гейт `bash tools/ci_gate.sh`.

## Что уже автоматизировано без MCP

Гейт `tools/ci_gate.sh` закрывает всё, кроме написания самих доказательств:
сборка с предупреждение=ошибка, аксиомный whitelist по каждой теореме,
печать утверждений (seal), конвенции/докстринги и мост в числовую
лабораторию. MCP/LSP ускоряют автора; гейт гарантирует результат.

> Замечание о воспроизводимости: lean4-mcp и LSP — инструменты разработки
> и НЕ участвуют в CI; приёмка остаётся детерминированной (lake + Mathlib
> по тегу + пять инструментов tools/).
