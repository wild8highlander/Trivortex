# CYCLORING — the documentation tree

The publication layer of the mini-research: the monographs in Markdown
sources plus their typeset renditions. Two collections:

```text
docs/
├── monograph/    ← THE BIG MONOGRAPH — the whole program as one book,
│                   RU and EN, each in .md, .docx and .pdf (6 files)
└── monographs/   ← THE THEOREM EDITION — one monograph per theorem,
                    Theorems 1–5, RU and EN, each in .docx and .pdf
                    (20 files)
```

## Which document to read first

- **the English reader** — start with
  [`monograph/monograph_EN.pdf`](monograph/monograph_EN.pdf): the full
  narrative of the five theorems, the W-ladder, the protocols and the
  honesty boundaries, with all five figures embedded;
- **the Russian reader** —
  [`monograph/monograph_RU.pdf`](monograph/monograph_RU.pdf) is the
  full-fidelity mirror, not a summary;
- **the theorem-focused reader** — the five theorem editions in
  [`monographs/`](monographs/) are self-contained dossiers, one per
  theorem, each with its statement, proof, protocol bindings and
  figures. They match the theorem sections of the two READMEs
  one-to-one.

## The rendition discipline

- **RU and EN are separate files** — separate page numbering, separate
  metadata, no half-translated volume; each rendition can be printed and
  cited independently;
- **the DOCX is the editable master**, the PDF is its LibreOffice render
  — the same pipeline as the parent repository's reading room, so both
  stacks stay typographically identical;
- **every document embeds the figures and quotes only protocol-bound
  numbers** from [`results/protocols/`](../results/protocols/) — the
  same discipline as the READMEs: a number without a protocol has no
  standing in print.

## Regeneration

The Markdown sources in `monograph/` are the committed sources of the
binary renditions. The DOCX/PDF renditions are regenerated by the
parent repository's document pipeline (pandoc → the navy-gold design →
LibreOffice), the same one behind `make pdf-library` at the repository
root. The renditions are committed, so reading the program requires no
document toolchain at all.
