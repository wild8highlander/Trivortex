Verification — Ladder V1–V4

An independent checker, a pytest guard, seven pinned toolchains and a formalization roadmap.

The principle

Numbers printed by the code that defines them are repetition, not verification. The TRIVORTEX ladder therefore lives in verification/trivortex/python/verify.py — a script that shares no code with the core document: it re-implements the closed form of Theorem 3.1, the Chaplygin combination, the Kirchhoff right-hand side and its own RK4 stepper from scratch, then checks the document's claims against its own arithmetic. Every run emits a JSON protocol (parameters, residuals, tolerances, wall time) — the same "numbers are bound to runs" discipline used across the repository.

Run it

python3 verification/trivortex/python/verify.py --preset quick    # ~0.5 s (CI)
python3 verification/trivortex/python/verify.py --preset default  # ~2 s
python3 verification/trivortex/python/verify.py --preset full     # ~35 s
python -m pytest verification/tests/ -v                           # 13 tests

Honesty notes

The C_Ch drift is a diagnostic, not a conservation law. The combination C_Ch(t) = r²(θ̇ − q·A_θ) with A_θ = 1/r oscillates together with the radial modulation of Theorem 3.1 — Section 6 of the document records its endpoint drift over the window [0, 100·T], and the ladder reports the same number as a diagnostic with no pass/fail role. The window-independent conserved quantities of the dynamics are the vortex integrals H, P, Q, I — and those are what V3–V4 certify. Any future language port must keep this separation.
