# POLYVORTEX — the documentation tree

The publication layer of the bench: the monographs in Markdown sources
plus their typeset renditions. Two collections:

```text
docs/
├── monograph/    ← THE BIG MONOGRAPH — the whole W-ladder program as
│                   one book, RU and EN, each in .md, .docx and .pdf
│                   (6 files)
└── monographs/   ← THE THEOREM EDITION — one monograph per
                    theorem/lemma: Theorems A, B, E; Lemmas C, D —
                    RU and EN, each in .docx and .pdf (20 files)
```

## Which document to read first

- **the English reader** —
  [`monograph/monograph_EN.pdf`](monograph/monograph_EN.pdf): the full
  narrative of the two layers, the five statements, the W-ladder, the
  protocols and the honesty boundaries, with the figures embedded;
- **the Russian reader** —
  [`monograph/monograph_RU.pdf`](monograph/monograph_RU.pdf) is the
  full-fidelity mirror, not a summary;
- **the statement-focused reader** — the five dossiers in
  [`monographs/`](monographs/) are self-contained, one per
  theorem/lemma, each with its statement, proof, protocol binding and
  figures. They map one-to-one to the theory sections of the two
  READMEs.

## The rendition discipline

- **RU and EN are separate files** — separate page numbering, separate
  metadata, no half-translated volume;
- **the DOCX is the editable master**, the PDF is its LibreOffice render
  — the same pipeline as the parent repository's reading room;
- **every document embeds the figures and quotes only protocol-bound
  numbers** from [`results/protocols/`](../results/protocols/) — a
  number without a protocol has no standing in print.

## Regeneration

The Markdown sources in `monograph/` are the committed sources of the
binary renditions, regenerated by the parent repository's document
pipeline (pandoc → the navy-gold design → LibreOffice) — the same one
behind `make pdf-library` at the repository root. The renditions are
committed, so reading the program requires no document toolchain.
