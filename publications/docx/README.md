# The DOCX shelf — 28 editable volumes, the twins of the PDF shelf

The same 28 documents as the PDF shelf
([`../pdf/`](../pdf/)), in editable Word format — one DOCX twin per
PDF, byte-generated by the same build from the same sources.

## The shelf map

| pattern | count | meaning |
|---------|------:|---------|
| `TRX-<nn>-<slug>_<LANG>.docx` | 24 | the twelve study monographs × RU/EN |
| `TRIVORTEX-Core-Monograph_<LANG>.docx` | 2 | the executable document as a book |
| `TRIVORTEX-Research-Compendium_<LANG>.docx` | 2 | the program map with every protocol |

## Why DOCX matters

The PDFs are the citable renditions; the DOCX files are the **editable
masters** of the reading room — the form reviewers, translators and
collaborators actually work in. Each DOCX carries proper field TOCs
(Word-native page fields), the navy-gold styling restyled into the Word
object model, and the same embedded figures and protocol-bound numbers
as its PDF twin.

## The sync contract

PDF ↔ DOCX pairs are produced in one build pass and mirror each other
content-wise; a divergence between a pair is a build bug. Rebuild both
shelves together:

```bash
make pdf-library     # 28 PDFs + 28 DOCX from committed sources
```

Edit flows never target the DOCX directly: the Markdown sources
(`research/TRX-*/monograph/` and [`../src/`](../src/)) are the masters,
the DOCX/PDF renditions regenerate from them.
